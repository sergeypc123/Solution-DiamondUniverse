# Fit-Gap анализ

Ниже указано, что для онлайн-аукциона уже есть в системах и что придётся добавлять. По интеграциям показан способ реализации на обоих этапах: в промежуточном решении (2 месяца) и в целевом (через год).

## Системы

| Система | Функциональность | Комментарий |
|---|---|---|
| ИС «Алмазы», существующая | Учёт камней и присвоение ID, существующая | Менять ничего не нужно |
| | Ведомости, существующая | Нужен новый вид ведомости под цифровой аукцион |
| | Отбор камней на цифровой аукцион, новая | Нет признака «отобран для онлайн-продажи» и статусов камня: в лаборатории, оцифрован, на торгах |
| | План и статус подготовки аукциона, новая | Такой функциональности нет |
| ИС «Логистика», существующая | Перевозка покупателям, в т.ч. за границу, существующая | Работает как есть |
| | Перевозка в лабораторию и обратно, новая | Нет таких маршрутов и этапов, лаборатории как получателя, сверки камней при возврате |
| ИС «Аукцион», существующая | Очные торги и определение победителей, существующая | Работает как есть |
| | Публикация данных оцифровки, новая | Система не умеет загружать и показывать данные оцифровки |
| | Онлайн-торги, новая | Нет внешнего доступа для покупателей, личного кабинета и приёма ставок |
| ИС «Бухгалтерия», существующая | Договоры и оплата перевозчиков, существующая | Договор с лабораторией заводится как обычный |
| | Акты и оплата услуг лаборатории, новая | Нет приёма актов от лаборатории |
| ИС «Лаборатория», новая (подрядчик) | Оцифровка камней, новая | Система подрядчика, требования к ней задаём в договоре |
| | Передача результатов и актов, новая | Нужно договориться о формате данных и API |
| Частное облако, новое (внешний сервис) | Хранение данных оцифровки и доступ покупателей, новая | Нужны договор и проверка ИБ. Нужно только на первом этапе, потом уходит |
| Excel-реестры, новые | Ведомость отбора, реестр передачи, реестр результатов оцифровки, реестр ставок | Нужны шаблоны и порядок заполнения. Только на первом этапе |
| Хранилище данных оцифровки, новое | Хранение данных на серверах компании | Появляется на втором этапе вместо облака |

## Интеграции

| Интеграция | Этап 1 | Этап 2 | Данные |
|---|---|---|---|
| «Алмазы» → «Логистика», существующая | Автоматически | Автоматически | Заявки на перевозку (существующие), перевозка в лабораторию (новые) |
| «Алмазы» → «Аукцион», существующая | Автоматически | Автоматически | Камни для торгов (существующие), признак цифрового аукциона (новые) |
| «Алмазы» → «Лаборатория», новая | Вручную, через Excel | Автоматически | Список камней на оцифровку (новые) |
| «Лаборатория» → облако, новая | Вручную, загружает подрядчик | Отключается | Данные оцифровки (новые) |
| «Лаборатория» → «Аукцион», новая | Вручную, через реестр результатов | Автоматически, по защищённому каналу | Данные оцифровки (новые) |
| «Лаборатория» → «Бухгалтерия», новая | Вручную, акты через ЭДО | Автоматически | Акты и счета (новые) |
| «Логистика» → «Бухгалтерия», существующая | Автоматически | Автоматически | Акты перевозчиков (существующие) |
| Реестр ставок → «Аукцион», новая | Вручную, вводит оператор | Отключается, ставки идут в «Аукцион» напрямую | Ставки покупателей (новые) |
| «Аукцион» → «Логистика», существующая | Автоматически | Автоматически | Победители торгов для отправки камней (существующие) |

Последней интеграции в описании кейса нет, но без неё камни победителям не отправить, поэтому я считаю, что она уже существует.
